Investor Harness 是什么

不是又一个 AI 工具，是套在 AI 上的执行纪律

Claude Code / Codex / OpenCode 已经够聪明——问题是它们做投研时不守纪律。Harness 是一层全 markdown 的规范栈，强制任何 LLM 按投研的规矩干活：

治幻觉

开工前强制 [Preflight] 取数计划 → 实际取数 → 每条事实带完整中文证据等级（公开事实 / 财报披露 / 市场共识 / 合理推演 / 待核验假设）→ 结尾强制"仍需补的资料"。

治健忘

.task-pulse 任务心跳 + .checkpoint 断点续跑 + 本地资料优先扫描——会话断了接着跑，历史研究是起点不是空白。

治不成体系

每次输出双份：对话贴全文 + 归档到 coverage/{ticker}/ 固定路径。半年后可 diff、可 review、可跨 skill 引用。

纯 markdown · 数据不出本地 · 全模型全 harness 通用 · MIT 开源

v0.9.5 · 深度研究升级

壁垒不许用形容词，空间不许只给大数

sm-company-deepdive 的三道硬闸

  • 壁垒五维量化——市场地位 / 品牌 / 技术 / 成本 / 转换成本，每维至少一个量化锚，先声明哪 1-2 维是决定性的
  • 竞对差距量化——差距表 + 追平年限与资本推演 + 壁垒侵蚀的可观测触发条件
  • 量价拆分——市场空间 TAM/SAM/SOM 自上而下 × 自下而上交叉验证；收入预测分业务线 量×价 逐条拆；预测收入 ÷ 空间 = 隐含份额逐年自检

两个新 skill

sm-valuation — 估值方法选择（PE/PB/PS/PEG/EV-EBITDA/DCF/SOTP）+ 三档测算 + 敏感性 + 同业对比 + 市场隐含预期反推。⛔ 不给目标价评级。

sm-quant-tape — 量化看盘 · 缠论结构：分型 / 笔 / 线段 / 中枢 / 三类买卖点 / 背驰 + 量能交叉验证。

共享框架沉淀在 core/moat-analysis.md 与 core/financial-metrics.md——所有 skill 用同一套口径。

v0.9.6 · deepdive 结论前置

§0 放最前面，但必须最后写

读者第一眼看到四行结论：

  • 核心逻辑 — 为什么值得关注 / 为什么是现在
  • 核心叙事 — 市场在讲什么故事 + 你判断的 gap
  • 走到什么位置 — 命题成型 / 验证中 / 叙事扩散 / 定价充分 / 逆转，配观察窗口
  • 核心关注点 — 未来 3-6 个月最能改变结论的 1-3 个变量

写作纪律反过来：先做完 §1-§13 底稿，每段末尾标结论支撑权重——

🔴 ★★★ 决定性（全篇 2-4 段）
🟡 ★★ 重要支撑（4-6 段）
🟢 ★ 背景铺垫（其余）

§0 每句必须能追溯到某段 🔴/🟡。未标权重不许写 §0；四行不许全写成正面。

读者体验 = 结论前置；写作纪律 = 结论由底稿 bottom-up 涌现。防的就是"先有结论再找证据"。

不依赖私有 API，纯文件总线——Claude Code / Codex / OpenCode 混搭也能跑；没有语音就用文字，协议相同。灵感来自"一对一任务 + 一个语音监工"的三人任务组实践。

v0.9.7 · 为什么要自主学习

"客户集中度呢？"——这是你第三次问了

每个分析师都有自己的问法：做模型总要问那几个假设，复盘总问那几类归因，深度报告总补问客户集中度、存货周转、老师教的那几个角度。

但每开一个新会话，AI 都从零开始——你只能一遍一遍重新说。

重复到第三次的时候，挫败感已经产生：它怎么还不会？

v0.9.7 的回答

把你的提问方式变成 skill 的一部分。

你问过三次的角度，第四次开始它先答，你不用再问。

而且全程自主运行——采集、归纳、生效、验证，你不需要说任何话，只保留一票否决权。

v0.9.7 · 机制

四段闭环 + 问题回家

① 采集（每次会话收尾静默做，≤200 tokens） 你的提问 / 追问 / 纠正 → .learning/question-ledger.jsonl 问题回家：按内容归属 home skill——deepdive 会话里问"折旧假设是不是太乐观" → 归 sm-model-check；问"今天为什么跌" → 归 sm-close-recap ② 归纳（每 3-5 次会话自动触发） 按 home 分组聚类 → 剥离标的抽象化（"H20 对华恢复对 FY27 收入的影响" → "单一{产品}在{地区}的出货边际变化对{财期}{业务}收入的影响"） 阈值：≥3 次 · ≥2 个标的 · ≥2 个不同日期 + 泛化测试 + 三重冲突检查 ③ 写回（自动生效进试用期，每轮 ≤3 条） 问法 → user-skills/overlays/{skill}.overlay.md 的「必答问题（新增）」 跨 skill 偏好 → .learning/learned-rules.md（全局）· 单标的 → coverage/{ticker}/questions.md ④ 验证（试用期 5 次使用，三信号自动跟踪） 成功判据 = 你不再需要问这个问题 → 转正；失败 → 自动停用（可一键恢复）

会话尾一行摘要：🧠 自动生效 2 条试用规则 · 撤销任一条说"撤销 L-xxx"。老师的问题清单可以"把这些问题学进去"直接高权威导入。

v0.9.7 · 为什么敢让它自动生效

自主 ≠ 失控：每条规则可逆、可审计、出不了工作区

统计门槛

≥3 次·≥2 标的·≥2 天，90 天滚动窗口。"经常问 ≠ 每次都要"——异动日才问的角度成案为条件必答，不污染平静期报告。

试用期

新规则先试用 5 次：原问题复现 ≥2 次或产出被连续忽略 → 自动停用。规则必须证明自己有用才转正。

不可覆盖域

证据分级 / 合规声明 / 数据源纪律 / preamble·postamble 步骤——学习规则永远碰不到。外发报告层的纠正也不会污染讨论层。

一票否决

"撤销 L-xxx" 一键回滚，"看看学了什么" 全量审计。每条规则带原话出处 + 事件 ID，台账可追溯。

学习产物全部留在你的 workspace（.learning/ + overlay），默认 git-ignore——
机制是开源的，但"懂你"这件事只属于你的本地。
