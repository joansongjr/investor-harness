# Business Line Analysis · 业务线逐条展开框架（v0.9.8 新增）

> 被 `sm-company-deepdive` §2 引用（sm-earnings-preview / sm-thesis 可复用其中的传导链与前景模板）。
> 目标：把"业务介绍"从官网式罗列变成**可判断、可证伪、可更新**的理解结构。"更细"细在切分维度 / 问题式必答 / 技术传导链 / 时效纪律，⛔ 不细在数字表——§2 内禁止任何量价测算表，测算一律归 deepdive §5 档 B。
> 所有事实必须带完整中文证据等级（公开事实 / 财报披露 / 市场共识 / 合理推演 / 待核验假设）。

## §0 技术类信息的源权威度优先级（硬约束）

2.c / 2.d 涉及技术路线、产品代际、标准演进的表述，引用源按以下优先级取，低层级源只作线索、结论尽量落在高层级源上：

1. **公司官方**：IR 新闻稿 / SEC·交易所 filing / 技术日 / 官网产品规格
2. **行业标准组织**：JEDEC / OIF / PCI-SIG / SNIA / IEEE 等的标准冻结与路线图
3. **权威产业研究机构的原始发布层**：TrendForce / DRAMeXchange / IDC / Yole / TechInsights / Counterpoint 等 newsroom 或原表（付费墙内的完整报告本机通常无账号，只引其公开发布层并注明）
4. **头部厂商官方 roadmap**：NVIDIA / AMD / 台积电 / 三星 / SK 海力士 / 美光 / 铠侠等的官方发布会与白皮书
5. **严肃科技媒体**（Tom's Hardware / AnandTech / Blocks & Files / ServeTheHome 等）：须注明其引用的一次源
6. **一般媒体与二手转述**：只作线索，标（待核验假设），须回溯至上述层级后才可支撑结论

## §1 业务线切分规则（三层切法）

【三层切法，全商业模式通用骨架】
- L1 = 公司披露分部口径（财报 segment / 管理层业绩会拆分），保证每条线收入数字可与 §5/§6 对账，⛔ 禁止自创与披露对不上的切法；公司完全不拆分时按产品线公开信息切并整段标"占比为合理推演"。
- L2 = 分部内按商业模式对应的"主导维度"再切一刀（见下表），选择标准：哪个维度造成的价格/毛利/竞争格局差异更大就按哪个切。
- L3 = 仅当单元占收入 ≥30% 或是当前多空分歧核心时才展开（如"800G × 某北美云厂商"），否则不切。

【停止条件】切到"同层各单元在 2.c 前景与 2.d 技术传导的答案开始不同"为止；两个单元 2.c/2.d 答案完全一致 = 切过头，向上合并。硬上限：L2+L3 业务线单元总数 ≤5，超出必须合并。

【合并阈值】收入占比 <10% 且不承载估值叙事、无独立催化 → 并入"其他业务"一段（合计 ≤150 字：占比、方向、有无减值/剥离风险）。例外强制单列：占比再小（<5% 也算）但承载估值叙事的期权型业务（传统公司的 AI 新业务、新平台导入、液冷/整柜新品类），且可以排最前——市场给的估值弹性在它身上。退出/剥离中业务单列 ≤80 字只写进度。

【排序】按"对当前估值/股价的解释力"排，不机械按收入：①有可日期化锚（业绩会问答被反复问及、有日期的公开报道）证明是多空分歧核心的线排第一；②给不出锚 → 按毛利贡献降序；③分部毛利不披露 → 收入占比降序。§2 开头一句话交代用的是哪一档排序规则；⛔ 无锚不得声称"市场分歧核心"。

【商业模式对照表】
| 商业模式 | L2 主导维度 | 本模式最关键必答 |
|---|---|---|
| 硬件/半导体/存储/光模块/元器件 | 产品代际 或 下游应用（二选一：哪个造成价/毛利/格局差异更大） | 2.b 客户卡位状态与代际进度锚；2.d 关键判别"代际内升级 vs 路线切换"（认证/产能/工艺能否继承） |
| 软件/SaaS/平台/互联网 | 计价单位 × 预算池 × 竞对集合（三要素任一不同即分开切；如同为订阅，seat 计价与 usage 计价必须分开） | 2.a 计价单位及其领先指标（RPO/billings/DAU/GMV）；2.d 计价单位冲击专项（agent 化对 seat 基数的改造、推理成本进 COGS、开源/平台自带吸收）；"技术变化"放宽为"技术/形态/入口变化" |
| 集成/ODM/EMS/IDC/电源液冷/服务 | 客户群 × 产品形态，判据 = 价值量逻辑独立（量/价/份额/技术暴露四因子至少一个明显不同才单切；区域产能不单独成线，作 2.b/2.c 必答项） | 2.b 客户结构与供应链位置事实；2.d 环节归属变化（交付单元上移/客户垂直整合——"谁来做集成"被改变是这类公司最大级别变量，必须单独回答） |

【防塌陷执行机制】收入占比 >15% 的业务线，2.a-2.e 每小段要么有内容、要么显式写一行"本线为何薄：无披露 / 非市场关注点"——塌陷必须可见，不许沉默。

## §2 输出规格（2.0 + 每线 2.a-2.e）

> §2 是全篇的判断主体。"更细"细在理解结构——怎么切、问什么、技术怎么传导、判断何时过期；不细在数字表。
> ⛔ §2 内禁止出现任何逐年量×价表、ASP 假设表、出货量预测表、分线毛利桥。数字测算一律归 §5 档 B，且受 §5 数据可得性闸门约束（基年每格能指到披露来源才准建表）。§2 只写"构成 + 升/降/持平 + 机制"。
> ⛔ 通用出口原则（覆盖本节全部必答项）：任何必答问题没有一次源时，合格答案是"未披露 / 无公开信息 / 无法判定 + 一句原因"，或"行业惯例为 X（市场共识，非公司口径）"，并把缺口喂给 §11。写出不确定本身就是信息；一句"未披露"比注水 200 字更合格。⛔ 禁止为满足必答格式补数字、补日期、补方向。

## 2.0 切分与排序声明（§2 开头一次性交代，80-120 字）

**必答**：
1. 切成哪几条线？L1（披露分部）→ L2 用了哪个主导维度、为什么在这层停？
2. 哪些小业务并入"其他"？合并理由（占比 + 与论点无关）。
3. 排序用的哪一档规则（分歧核心前置 / 毛利降序 / 收入降序）？若称"分歧核心"，必须带可日期化锚（哪场业绩会问答 / 哪篇有日期材料）；给不出锚，静默退到毛利/收入降序，交代句不出现"分歧"字样。

**切分规则**（三层 + 停止条件 + 合并阈值 + 商业模式对照表）：按本 SKILL 附录《业务线切分规则》执行。硬约束：
- ⛔ L1 必须锚定披露口径，§2 的占比与 §5/§6 财务口径必须对得上账
- ⛔ L2+L3 单元总数 ≤5；同层两个单元在 2.c/2.d 的答案完全一致 = 切过头，向上合并
- ★ 鼓励一次"有理由的换刀"：除报表口径外，若存在一个更能解释本公司毛利率/增速差异的第二切分维度（商业模式 JDM/ODM/自有、代际、客户类型、区域），用一张 ≤4 行的小表展示并说明为什么是这个维度；找不到就不硬找
- 🔧 防塌陷：收入占比 >15% 的线，每小段要么有内容、要么显式写一行"本线为何薄：无披露 / 非市场关注点"
- 🔧 同 ticker 对账：本 ticker 已有历史产出时，必须 diff 上一份的关键数字（排名/份额/毛利率/产品状态/客户口径），冲突显式列入待核验假设，禁止两版各说各话

## 每条业务线固定 5 小段（2.a-2.e）

⛔ 成稿中每个小段标题必须写成**结论句**（如"800G 是唯一增长引擎，年降由放量对冲"），栏目名（"产品前景""客户结构"）只存在于本 skill 骨架里，不出现在成稿标题。判断前置——PM 扫标题 2 分钟要能带走判断脉络。

### 2.a 生意模型与增长引擎：卖什么、向谁收钱、怎么收、过去靠什么涨

**必答**（每问自带出口）：
1. 这条线卖的具体是什么（写到型号/代际/服务形态层级，不是品类名）？交付单元一句话（卖盒子/卖片子/卖席位/卖工时/卖整柜/产品+耗材组合）。客户不买它时的替代方案是什么（竞品/自建/不做）——替代方案形态决定定价天花板。
2. 谁付钱、怎么收：计价单位（按颗/按台/订阅 seat/按量/抽成/项目制/license+维护/BOM 加价）？由此点名哪个披露指标是本线领先指标（RPO/billings/在手订单/DAU/GMV）。定价节奏（年度议价/季度/现货/招标）为**条件必答**：有公司口径（业绩会/招股书原话）写公司口径标（财报披露）；无则允许"按行业惯例通常为 X（市场共识，非公司口径）"或"未披露"。
3. 收入占比 + 近 2-3 年增速各一句话，注明口径年份。分线毛利：**有披露才写数**；无披露只写"高于/低于公司整体 + 机制原因"标（合理推演），⛔ 禁止给任何百分比或区间数字。L2 子线无收入拆分披露时只做定性排序（最大/次之）并明写"未单独披露"，⛔ 禁止倒算占比。
4. 增长引擎归因：过去 2-3 年增长里，量/价/份额/品类扩张（含并表汇率）各自是正/负/中性贡献？只要方向和主次，不做表。有管理层归因原话引原话（财报披露）；无披露写方向归因标（合理推演）并明写"公司未披露 X，无法验证"。
5. （条件触发项）收入确认：仅当确认方式扭曲季度节奏或构成投资争议（完工百分比/验收制/总额净额法）时一句话点明，否则整句不写。会计细节归 §6。

**证据锚**：年报/招股书分部附注与业务描述、前五大客户披露（财报披露）；业绩会原话（财报披露，注明管理层口径）；公开定价页（公开事实）。
**⛔ 禁止**：官网/招股书式罗列（"深耕多年""广泛应用于""客户覆盖国内外知名大厂"）；历史沿革与荣誉资质（归 §1 或删）；产品参数表当分析。
**★ 好写法**：增量贡献占比一行算术（"X 线贡献了总收入增量的 92%"）——有披露分部数据时鼓励做，把"谁在驱动增长"钉死。

### 2.b 客户与卡位现状：在客户那里是主菜还是配菜

**必答**：
1. 客户结构：前几类客户是谁（能点名就点名并标证据等级；客户名来自媒体推断时单独标（市场共识/合理推演），⛔ 禁止把推断客户写成事实后再给它配供应链定位）。客户集中度：有披露引披露（前五大占比、>10% 单一客户），无披露写"集中度未披露"。
2. 供应链/工作流位置（按商业模式选用口径）——硬件与集成类：独供/主供/二供/导入中/送样中，**"公开信息无法判定（已查来源类型：X）"是合法完整答案**，位置不明时列入待核验假设；⛔ 唯一硬线是不许把导入中/送样写成已供货。软件平台类：产品在客户工作流与预算里的位置（记录系统/工作流枢纽/单点工具），粘性机制**点名类型即可**（数据沉淀/流程嵌入/生态集成/仅剩合同期），机制的展开与持久性论证归 §3，本段一句话 + "详见 §3"。
3. 份额趋势在拿还是在丢：**方向判断必须写出交叉依据**（客户财报分部印证/公司业绩会明示/公告 design win），写不出依据只能答"不可判"。⛔ 禁止用分部收入增速直接倒推"份额在升"写成事实（可写推理并标合理推演）。
4. 新品/新客户导入最新可验证节点（带日期）：**无公开节点时写"无公开可验证节点"即合格**。代际进度差只允许用双方公开里程碑日期相减得出（"对手 X 月宣布量产、本公司 Y 月宣布送样"）；无公开锚点只写三档定性（领先/大致同步/落后）标（合理推演），⛔ 禁止给"落后 N 个季度"式无源精度。
5. ★ 客户不具名时的代理观测法（强烈鼓励）：推断客户身份标（合理推演）后，指定至少一个可操作的印证回路——用客户自己的财报分部/招标公告/产业链公开数据做交叉验证（例：推断第一大客户为某连接器巨头 → 用其 10-Q 对应分部增速印证）。不停在"未披露"。

**证据锚**：财报客户集中度披露、业绩会问答原话（财报披露）；客户方 capex 指引与公开供应商信息（公开事实/财报披露）；供应链媒体报道必须是本次会话实际检索到的（媒体名+日期）标（市场共识），检索不到就写"未检索到可引用的公开报道"。切换/认证周期只在有公司或客户公开表述时写月数，否则只写机制关卡不写时长。
**⛔ 禁止**："深度绑定大客户/客户资源优质"回避具体位置；无出处份额百分比；allocation 传闻不带来源日期。
**分工指针**：切换成本"为什么守得住"归 §3；竞对全景归 §4；本段只写状态事实。

### 2.c 产品前景：需求端拉力 × 供给端压力 → 判断行

**按固定三段模板写（见附录《前景模板》），每段 2-4 句，判断收敛成独立一行。**

**必答**：
1. 需求端：未来 4-8 个季度拉动本线的 1-2 个具体可观测变量（下游 capex/新平台放量/单机用量/渗透/预算池扩缩——软件类先答"吃客户哪个预算池"）？最新公开读数 + 日期 + 证据等级；**无公开读数或读数在付费墙内时，明写"变量可观测但无公开读数"只给方向**，缺口喂 §11。需求属性：增量型/替代型/换机周期型；天花板信号（出现哪个读数就该承认到顶）。政策仅当真是本线主驱动（管制/补贴/信创）才写，⛔ 不作固定栏目。
2. 供给端：**只保留一行净判断**——"谁在扩产/切入（有公开公告才点名），压力先落在价还是量，依据 X，竞对明细见 §4"。扩产/新玩家的逐家展开归 §4。价格方向：有公开价格序列写序列口径 + 日期；无公开口径允许用可核验代理变量（毛利率趋势/业绩会原话/公开招标价）推断方向标（合理推演）；两者皆无时**"价格方向不可知（无公开口径且无可靠代理）"是合格答案**，⛔ 禁止编拐点日期。
3. 判断行（固定句式，缺席 = 本小段不合格）："未来 12-24 个月本线增速相对【公司整体/行业】判断为 ↑/→/↓（数量级：快于/同步/慢于），押的核心假设是【一条】，最先证伪它的公开可观测信号是【一条】。（证据等级）"三段皆无一次源时允许只写方向 + 机制整段标（合理推演），并附一句"若拿到 X 数据可修正此判断"喂 §11。

**⛔ 禁止**："受益于 AI 浪潮/前景广阔/空间巨大"无变量判断；只写需求不写供给；给市场规模数字（含数量级区间）——空间归 §5，本段只写变量读数与方向；判断不给前提和证伪信号。
**分工指针**：多年期空间/TAM/量价表归 §5，§5 引用本段判断行编号、不得换个说法重写需求叙事。

### 2.d 技术变化的利好/利空传导链（§2 权重最高小段）

**必答**：
1. 未来 1-3 年本线暴露在哪些技术路线变化下？只写"正在发生"或"有客户路线图/标准冻结/新品发布公开节点"的，不写科幻。平台/消费/互联网公司把"技术变化"放宽为"技术/形态/入口变化"（内容平台冲击、入口迁移、agent 化改造交互与计价）。
2. **每条业务线全链展开上限 2 条**（2.0 声明的多空分歧核心线可放宽到 3 条）（选成熟度最高或分歧核心的），按六环模板写全（见附录《传导链模板》）；其余变化压成一行（↑/↓/→ + ≤15 字机制）进末尾矩阵。⛔ 禁止为凑链数把无实质关联的变化硬展开——"该变化与本线无实质关联"一句带过即合格。

### 2.e 最近 90 天边际变化：每条事件回连它验证或削弱了哪个判断

**必答**：
1. 报告日前 90 天窗口内，本线的订单/客户/新品/价格/竞对/产能类公开事件，**有事实的类逐条列出、空类直接跳过**（⛔ 不逐类填充）。每条一行：日期 + 事实 + 来源 + 回连（"强化/削弱/不改变 2.c 判断行或 2.d 链 N 的前提"）——只罗列不回连 = 白写。倒序排列。
2. 订单类事件仅收公司公告/业绩会/交易所披露口径；媒体传闻订单只能标（待核验假设）且写明为传闻。
3. 末尾一句话：90 天净方向——边际向好/向差/无变化。
4. **窗口内无事件时，写"截至 YYYY-MM-DD，过去 90 天未检索到与本线直接相关的公开事件，净方向：无变化"即为完整合格作答**，⛔ 禁止旧闻改期或凑边角事件。

**证据锚**：必须来自本次任务实际执行的 90 天时间限定检索；⛔ 训练记忆里的"新闻"不得计入本段；每条必须可日期化，"近期/据悉/有消息称"不允许出现。
**分工指针**：本段与 §7 共用同一次 90 天检索，禁止两套事实清单。事件只影响单一业务线 → 本段完整写；跨业务线或公司层面（回购/人事/整体指引/大客户 capex 整体表态）→ §7 完整写，本段一行编号指回。同一事件只落一处。

## 附录 A：技术变化传导链模板（六环）

每条全链展开的变化独立成段，六环齐全、逐环标证据等级；正文收成 3-4 句连贯段落，编号是写作检查清单不是输出格式：

- ① **变化是什么**：一句话（什么在替代/升级什么）+ 成熟度档位（论文期/样品期/小批量/放量期）+ 推动方（客户/标准组织/竞对）+ 最新公开时间锚（发布会/路线图/量产公告 + 日期）
- ② **改变的约束/环节**：以前做不到/太贵/够不着的什么变了；落在价值链哪一环 + 关键判别（代际内升级 vs 路线切换 / 环节归属变化 / 计价单位冲击，按商业模式选用）
- ③ **对本线的机制**：量/价/份额/毛利逐项给"方向 + 机制"；无影响写"中性"，真不可知写"**无法判断 + 一句原因（待核验假设）**"——与"中性"严格区分，⛔ 缺项不填才打回，"无法判断"是合格填答
- ④ **净判断**：利好/利空/中性/双刃 + 强度 + 时间刻度（何时开始进本公司损益表）+ 成立前提一条
- ⑤ **已观察证据**：1-3 条带日期一次源，各标证据等级；**反向证据若存在必须同列**；无证据明写"尚无可观察证据，属合理推演"
- ⑥ **反转/证伪信号**：看到什么公开可观测信号即认错

硬规则：a) 必须写明从哪一环开始是推演；b) 同一变化对不同业务线判断可以相反，分开写不合并；c) 公司级技术变化（如整机架构转向）允许在 §2 开头写一次完整链，各线内只写 ③④ 两环并指回，不逐线重复全链。

**示例（仅示意链条写法。⛔ 示例中全部日期与事实截至写作该示例时点，禁止作为证据直接复用进任何报告；引用类似事实前必须本次检索重新核验）**：CPO 之于可插拔光模块业务——① CPO 将光引擎与交换 ASIC 共封装，替代交换机侧部分可插拔场景；GPU 平台厂已发布 CPO 交换机并给出出货时间表，成熟度 = 小批量期（公开事实，带发布日期）。② 路线切换：封装形态与采购方式改变，新增外置光源/光引擎等采购环节，认证关系部分重置。③ 量——交换机侧可插拔端口被替代，利空；GPU 侧主力连接仍以可插拔承接，1-3 年替代范围有限（市场共识，注明机构与发布日期）；价——中性；份额——具备硅光与外置光源能力、靠近平台生态的厂商相对受益（合理推演，自此环起为推演）；毛利——新品类毛利结构未知（无法判断：无任何公司披露，待核验假设）。④ 对无硅光能力的纯可插拔厂商偏利空，压力自放量期起放大；前提 = CPO 部署不因可维护性/良率递延。⑤ 平台厂公开发布（公开事实）；头部模块厂业绩会披露硅光/CPO 布局（财报披露）。⑥ 反转：CPO 部署公开递延，或头部云厂商表态锁定可插拔架构。

## 附录 D：时效规则

1. **双日期标注**：§2 开头强制标"取数截止日期"（本次检索最新日期）与"最旧关键判断依据日期"（支撑各判断行的数据点里最老的那个）；后者超过 6 个月，对应业务线自动标"判断依据老化，待更新"。
2. **三级取数窗口**：结构性事实（2.a/2.b 骨架）允许引最近一期年报/招股书；方向判断（2.c/2.d）优先用最近 2 个季度内带日期数据点，拿不到时**不逼造读数**——判断自动降级标（待核验假设）+"判断依据老化"，缺口喂 §11；边际变化（2.e）只收 90 天窗口。
3. **现状表述必须本次检索验证**：当前定价/产品状态/客户口径/竞对格局类"现状"陈述无法验证时保留但标"截至 X 日期口径，未验证是否最新（待核验假设）"。
4. **降级机制**：市场共识级的份额/allocation 表述必须带来源 + 日期；首报日期不可考的直接按（待核验假设）处理，⛔ 不要求也不允许补造日期；超 180 天无后续确认自动降级为待核验并在下次更新优先核。
5. **更新触发**（任一命中即局部刷新，不全文重跑）：本公司或前两大客户财报/指引修正；平台方/客户发布新路线图或新品；主供二供关系变化公告；价格公开数据拐点；管制/关税政策落地；距上次更新超一个财报季。
6. **局部刷新协议**：触发后只重写 2.e + 受影响的 2.c/2.d 条目，未受影响段落标"沿用 YYYY-MM-DD 版判断"；判断行与链净判断视为有版本的观点——**箭头变动必须写"上次判断 vs 本次判断 + 变动原因"，⛔ 禁止无痕改箭头**；复用旧稿不允许原样照搬超过一个财报季。
