# SM Infographic · 一图复盘

这个 skill 解决"研究结论要能被一屏读完、还能被转发"的问题。它不是把报告排版成图，而是**强制做一轮信息压缩**：先写数据底稿，再把底稿里权重最高的 20-40 个事实渲染成一张图。图是结论的展示层，底稿是它的证据层——两者必须一一对应。

## 强制流程（硬约束）

> ⛔ **任何分析输出之前**，必须严格执行 [`../../core/preamble.md`](../../core/preamble.md) 的 6 步开始前流程
>
> ⛔ **任何输出完成之前**，必须严格执行 [`../../core/postamble.md`](../../core/postamble.md) 的 8 步结束后流程
>
> 输出归档按 [`../../core/output-archive.md`](../../core/output-archive.md) 命名规范
> 输出验收按 [`../../core/acceptance.md`](../../core/acceptance.md) 清单逐条自检

**先底稿后作图（不可颠倒）**：Step 1 产出数据底稿 md（结构见下），Step 2 才渲染 HTML。⛔ 图上出现底稿没有的数字 / 判断 = 违规（同 deepdive 矩阵规则：展示层不得成为第二个无证据结论层）。

**技术与产业口径**引用源按 [`../../core/business-line-analysis.md`](../../core/business-line-analysis.md) §0 权威度优先级；一致预期必须注明来源机构（公开聚合口径注明"公开卖方一致预期"），⛔ 禁止自己编"市场预期"。

## 模式判别

| 用户说 | 模式 |
|---|---|
| "X 财报一图 / 一图看懂 X 季报 / X 业绩会一张图" | **A 公司财报一图** |
| "X 板块 N 月复盘一图 / 一张图看 X 行情和财报" | **B 板块期间一图** |
| 只说"一图 / 一页图"且上下文是单公司财报 → A；是板块 / 主题 / 一段时间 → B；判不出 → 问一句 |

## 必答问题

**模式 A（公司财报一图）**：
- 这一季**最重要的一个预期差**是什么（它就是大标题，必须带数字）
- 关键指标 vs 一致预期各差多少（超 / 低 + 百分比）
- 增长引擎分几层，每层现在走到哪（主力 / 扩展 / 下一增量 / 接棒）
- 市场正在流传哪些**错误或不精确的口径**，原话是什么（信息准确性核验）
- 管理层前瞻里，哪些是**指引**、哪些只是**展望 / 计划 / 客户预测**（口径必须分开）
- 主要瑕疵是什么（禁止全图正面）

**模式 B（板块期间一图）**：
- 这段时间板块的**一句话主线**是什么
- 报表端：哪几家公司的财报验证 / 证伪了主线（每家 1-3 个关键数字）
- 事件端：区间内改变认知的事件时间线（带日期）
- 行情端：区间指数 / ETF 涨跌多少，关键拐点日发生了什么
- 主线怎么映射到可观察标的（**只列映射与逻辑，不作推荐、不给金股**）
- 风险行：什么信号出现说明主线要反转

## Step 1 · 数据底稿（.md，先写先归档）

结构固定四块：

1. **事实清单**：每条 = `编号 | 事实（含数字） | 日期 | 来源 | 证据等级`（完整中文五档）。一致预期条目必须带来源机构；行情条目必须带区间起止日期与涨跌幅口径（价格 / 全收益）
2. **图上判断清单**：大标题、副题、hashtag 结论、点评行——每条判断标注"依据事实 #N"
3. **信息准确性核验底稿**（模式 A 强制 3-6 条）：`市场流传口径 → 原话 / 原文 → 判定（确认 / 修正）→ 来源`。这一块的价值 = 把业绩会被媒体和转述扭曲的口径纠正回来，是全图可信度的锚
4. **仍需补的资料**（postamble 标准段）

## Step 2 · 一图渲染（.html 单文件）

### 通用版式纪律（两模式共用）

- **标题即结论**：大标题 = 最大预期差 + 数字（"FY28 目标升至 $18B"），⛔ 禁止"X 公司 2QFY27 业绩点评"式无信息标题；副题一句定调
- **颜色语义固定**：绿 = 超预期 / 利好，红 = 低于预期 / 风险，橙 = 中性 / 待验证，蓝 = 中性事实。⛔ 不许用颜色装饰无判断的数字
- **每个 vs 都写参照物**：+37% 必须写清是同比 / 环比 / vs 一致预期；一致预期数值直接标在旁边
- **口径纪律**（本 skill 的灵魂，参照口径示例：`"这是部署计划，不应写成已落地刚性订单"` / `"$120B 是条件性累计门槛，不是已锁定订单"`）：凡管理层展望 / 客户预测 / 意向协议 / 累计门槛类数字，图上必须**就地**带一句口径限定，不许放脚注了事
- **页脚双件套**：① 口径与来源行（数据源 + 关键日期 + 取数截止日）② 合规声明（不构成投资建议 + 需持牌分析师复核）
- **工程约束**：单文件 HTML、内联 CSS、⛔ 无外链字体 / JS 库 / 图片（条形图用 div / 原生 SVG 画，参照图的图表复杂度用不到图表库）；正文字号 ≥12px；总字数上限 ≈ 800 字（图是压缩的产物，塞不下 = 压缩没做完，回底稿删）

### 模式 A 版式（横版 16:9，1920×1080 可导出）

自上而下五个区：
1. **头部**：结论式大标题 + 副题；右上角小字（季度截至日期 / 币种口径）
2. **KPI 卡片行**：4-5 张（收入 / 核心分部 / 利润率或 EPS / 下季指引），每张 = 数值 + 同环比 + vs 一致预期一行绿/红字
3. **主体左右分栏**：左 = 中期锚（收入目标 / 毛利率路径的简图，3-4 根条即可）；右 = 增长引擎分层 bullet（每层 = 彩点 + 加粗定位词 + 一句机制，参照"Scale-out｜近端主力"写法）
4. **信息准确性核验块**（或与"新增量"块并排）：确认 / 修正两色标签逐条列
5. **底部条**：利润率与现金流一行 + 口径警示一行（灰底）+ 一句话点评

### 模式 B 版式（竖版长图，宽 750-1080px，适配微信转发）

自上而下编号段落：
1. **头部**：期间 + 板块 + 结论式标题；**投资逻辑总结框**（核心结论 3-5 行 + 风险提示 1 行，红/深色框）
2. **① 报表验证**：每公司一张小卡（公司名 + 最大数字 + 2-3 行关键 beat/miss + 来源日期小字），一行 3-4 张
3. **② 事件时间线**：按日期列区间内改变认知的事件（发布 / 政策 / 产品），每条一行
4. **③ 行情复盘**：区间指数 / ETF 走势（SVG 折线，关键日期标注文字气泡：几号发生什么、当日涨跌），旁边归因 3-4 行
5. **④ 主线映射**：2-4 条主线卡（主线名 + 一句逻辑 + 相关标的列举）。⛔ **不做"金股 / 推荐"段**——映射是观察清单不是建议，卡片上不出现评级、目标价、"推荐"字样
6. **页脚**：资料来源逐条带日期 + 合规声明

## 约束

- ⛔ 先图后稿 / 只交图不交底稿 = 未完成（图上数字无法溯源）
- ⛔ 图上任何数字 / 判断在底稿找不到对应条目 = 违规
- ⛔ 全图无一处红色 / 瑕疵 / 风险 = 压缩造假，打回（参照图都有 #主要瑕疵 / 风险提示行）
- ⛔ 行情复盘不写区间起止日期与数据截止日 = 违规
- ⛔ 把展望 / 计划 / 客户预测 / 条件性门槛写成指引或订单 = 违规（口径限定必须就地标注）
- ⛔ 出现评级 / 目标价 / "金股" / "推荐买入" = 违规（compliance.md 红线）
- 一图默认交付中文；术语（Scale-up / NBM / FDE 等）保留英文原词不硬译
